# F2 bounded exception-entry contract — proposed, NOT IMPLEMENTED

## Architectural scope
32-bit protected mode, CPL0 handler CS=0x08, flat writable SS=0x10, single CPU, non-PAE paging. No TSS, CPL3, USER mapping or recovery. VM86, task gates, CET, SEV-ES and AMD secure execution are outside the accepted CPU contract. Guests explicitly use `-cpu qemu32 -smp 1`; QMP must confirm CPL0, CR0.PE/PG/WP, CR4.PAE/CET clear and EFER.LMA clear. Optional delivery is never misdecoded as no-error.

Exact vector/profile table (exhaustive0..31): hardware-error8,10,11,12,13,14,17; unsupported-without-frame-decoding21,29,30; no-error0,1,2,3,4,5,6,7,9,15,16,18,19,20,22,23,24,25,26,27,28,31. Intel table establishes #CP21 has an error if delivered; AMD29/30 error/layout remains NOT VERIFIED after publisher/PDF network failures, outside the accepted contract. All three unsupported stubs immediately CLI/CLD, install kernel data selectors using EAX scratch (no saved-frame claim), align a C call, and pass only their software vector to a separate ->! unsupported handler. They never read or construct any CPU-frame reference and never return, regardless of hardware-error presence. All other exception stubs use the68-byte prefix below. Software INT n is not an admissible error-code exception oracle; it does not manufacture the architectural exception's hardware error. The old exception_pushes_error_code bool becomes explicitly a baseline mandatory-error predicate, NOT a universal no-error classifier; dispatch instead uses shared three-way FrameKind metadata. Tests must enforce unsupported21/29/30 distinctly while preserving inherited supported-vector identities.

Same-ring entry pushes EFLAGS, CS, EIP, then optional error; low addresses [error?, EIP, CS, EFLAGS]. No old ESP/SS exists on same-ring entry. A privilege transition adds old ESP/SS above EFLAGS. Saved CS&3 identifies origin; PF.user is not origin authority. VM86 is excluded.

## Proposed minimum correction
Replace ONLY CPU exception vectors0..31 with explicit assembly entry stubs feeding one extern C ->! Rust fatal function. Keep the existing IRQ subsystem, GDT, PIC and boot entry untouched. No exception returns. Keep historical PF diagnostic spelling for inherited fixture compatibility.

Each no-error stub pushes synthetic0 then vector; each hardware-error stub pushes only vector. Common path does CLI, CLD, PUSHAD, saves DS/ES/FS/GS as zero-extended32-bit values using SS-segment stack writes, then sets all four data selectors to0x10. Preserve original registers before using EAX scratch. Pass pointer to a fixed68-byte prefix, NOT a reference to optional stack fields. The SS default segment for ESP/EBP addressing allows building the prefix even with null DS/ES/FS/GS. Never change SS or try to load arbitrary saved selectors during fatal handling.

Prefix byte offsets (all u32, repr(C), align4):
0 gs;4 fs;8 es;12 ds;16 edi;20 esi;24 ebp;28 pushad_esp;32 ebx;36 edx;40 ecx;44 eax;48 vector;52 error;56 eip;60 cs;64 eflags; size68.
PUSHAD ESP denotes the normalized vector address (prefix+48), not pre-exception ESP. Same-ring pre-exception ESP is prefix+68, computed as a scalar only, not a read. Software-saved segment words represent selectors, not descriptor caches. Error presence is vector/profile metadata; synthetic0 is not a CPU error. Hardware CS high16 bits are not semantic selector bits.

Rust receives only the mandatory prefix. Optional oldESP/SS is decoded by a separate bounded slice API for synthetic tests; production fatal handling never reads the tail. Future real lower-privilege entry requires F3/F5 hardware verification. Compile-time size/offset assertions must bind assembly literals to Rust. An explicit 16-byte pre-CALL stack alignment is imposed by `and esp,-16; sub esp,12; push frame_pointer; call fatal`; fatal C entry ESP is12mod16. Saved frame remains above scratch/alignment area. The C ABI call never returns; defensive CLI/HLT after it. FPU/SIMD extended state is not saved because no return and target disables SSE/softfloat; do not claim resumable ABI.

## Fatal safety
CLI before any Rust/data access; one atomic first-entry latch. Reentry (including NMI nesting) goes immediately to CLI/HLT without formatting. Only fixed literal/hex diagnostics using bounded direct COM1 polling; no allocator/page-map/VGA/PortAllocator guards, heap allocation, unwinding or shell return. Capture CR2 before diagnostic output forPF. Static count/info compatibility may be retained only without introducing lock edges. Hardware interrupt gate preferred for CPU exceptions, DPL0. No IRET on fatal exceptions; IRQ return remains existing compiler ABI and separately regression-tested.

## Double fault policy
Vector8 hardware error is zero; saved CS and EIP for abort are undefined, not origin/restart oracles. Do not expose #DF CS&3 as reliable origin. Ordinary-stack handler can terminally report only if CPU delivery succeeds with usable kernel SS/ESP. Corrupted/exhausted stack can prevent delivery and triple-fault. The Rust latch does not protect hardware delivery or pre-latch stub work. No claim of robust containment; independently provisioned emergency/task stack policy is an explicit F3 prerequisite, not implemented here. No deliberate stack-overflow recovery.

Preserve trigger symbol/context and actual #UD trace; no IRQ may intervene in destructive setup. Runtime_red_01 compiled and reached terminal vector06 without double-fault, so is PASS control, not RED.
